## Основные находки

1. Картинки дают около 72% проверенного сетевого объёма. Фон velvet-hour-bar.webp весит 431 916 байт. Пять фонов выбора города вместе весят 751 106 байт; на стартовом экране использованы полные изображения без lazy loading. Первым кандидатом на оптимизацию являются маленькие превью городов и отложенная загрузка фоновых изображений.
2. rulesError-7WYr0MZJ.js: 117 518 байт gzip / 356 949 байт после распаковки. game-B7XOqP3W.js: 62 756 / 185 261 байт. Сжатие снижает сетевой объём, но слабому устройству всё равно требуется обработать распакованный JavaScript. Для оценки этой нагрузки нужен профиль CPU.
3. Скрипты и CSS с хешами имеют public, max-age=31536000, immutable. Проверенные WebP имеют public, max-age=3600, must-revalidate. Это не означает обязательное повторное скачивание картинок каждый час: браузер может проверить актуальность условным запросом.
4. Production использует lounge-panel-painted-v1.webp размером 99 320 байт. Новые локальные текстуры surface-*.webp не обнаружены в инвентаре этой страницы. Поэтому этот замер нельзя считать проверкой всех последних локальных изменений.
5. Ширина мобильного экрана не эмулирует слабый процессор. При 390 × 844 режим остался full. В локальной реализации Auto выбирает Lite по saveData, числу потоков ≤4 или памяти ≤4 ГБ; при отсутствии этих подсказок облегчённый режим не гарантирован.

## Что измерить не удалось

Доступный браузер не предоставляет профилирование FPS, памяти, CPU и Performance API для LCP/INP. Попытка получить независимый мобильный аудит PageSpeed завершилась HTTP 429: исчерпана квота API. Эти показатели не оценивались по скорости выполнения команд или визуальному впечатлению.

Следовательно, подтверждены размеры ресурсов, сжатие, кеширование и отсутствие горизонтального переполнения стартовой сцены. Плавность на слабом Android и внутри Telegram остаётся непроверенной. Для неё необходим запись профиля на реальном устройстве либо браузер с доступным CPU/network throttling и Performance profiler.
